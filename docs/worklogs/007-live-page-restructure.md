# Live 페이지 구조 재편

> 소급 기록 — 2026-09-01 작성. 실제 작업은 2026-08-31.

## 1. 한 줄 요약

Live 탭을 "제보 구경하는 곳"에서 **"Q&A가 중심인 곳"**으로 바꾸고, GPS 인증 여부에 따라 화면 구성이 달라지게 했다.

## 2. 왜 만들었는가

Q&A([006](006-realtime-qna.md))를 만들고 나니 Live 페이지에 자리를 정해줘야 했다. 그런데 그 자리는 원래 "GPS 연동을 켜면 인증된 관광지의 제보 스트림을 보여주는" 임시 구현이 차지하고 있었다 — 원래 기획에서 Q&A 스트림이 들어갈 자리를, Q&A가 없던 시절에 제보로 대신 채워둔 것이었다.

Q&A가 실제로 생겼으므로 그 자리를 원래 주인에게 돌려준 작업이다.

## 3. 구현한 것

- Live 페이지 구조를 GPS 상태에 따라 두 가지로 고정
- "전체 LIVE Q&A" — 관광지 구분 없이 오늘의 활성 질문 (조회 전용)
- "내 현장 Q&A" — GPS 인증된 관광지의 질문 (여기서만 답변 가능)
- 인증 상태를 3분마다 조용히 재확인
- 개별 제보 스트림을 Live 메인에서 제거

## 4. 동작 흐름

```
GPS 연동 OFF (기본값)
   [🔥 HOT SPOTS]  →  [💬 전체 LIVE Q&A]

GPS 연동 ON + 현장 인증 성공
   [📍 내 현장 Q&A]  →  [🔥 HOT SPOTS]  →  [💬 전체 LIVE Q&A]
        ↑ 여기서만 답변 가능

[인증 판정]
GPS 토글 ON
→ 현재 위치 → POST /api/spots/nearby (반경 500m)
→ 가장 가까운 후보 1곳
→ POST /api/reports/verify-location 으로 재확인
→ 성공하면 "내 현장 Q&A" 노출
→ 3분마다 조용히 재확인 (자리를 뜨면 자동으로 사라짐)
```

## 5. 주요 파일

- `livespot_app/lib/screens/live/live_screen.dart` — 구조 전체
- `livespot_app/lib/widgets/global_qa_list.dart` — 전체 LIVE Q&A (조회 전용)
- `livespot_app/lib/widgets/qa_section.dart` — 답변 가능한 Q&A 목록
- `livespot_backend/app/api/questions.py` — `GET /questions/recent` 추가

## 6. 핵심 코드 / 개념

**GPS 토글 기본값은 꺼짐**

```dart
bool _isGpsVerified = false;  // 탭을 열자마자 위치 권한 팝업이 뜨는 걸 피한다
```

**여러 관광지가 주변에 있을 때 아무거나 고르지 않는다**

가장 가까운 후보 **하나**를 골라 서버 인증(`verify-location`)으로 다시 확인한다. 확인에 실패하면 다음 후보로 넘어가지 않고 "인증된 관광지가 없어요"라고 표시한다. GPS만으로 관광지를 골라잡지 않는다는 규칙([002](002-report-gps-verification.md))을 여기서도 지킨다.

**조용한 재확인** (`silent: true`)

3분마다 인증을 다시 하는데, 매번 로딩 스피너를 띄우면 사용자가 질문을 읽는 중에 화면이 깜빡인다. 그래서 주기적 재확인은 **상태가 실제로 바뀔 때만** 화면을 갱신한다.

**이 타이머는 화면 표시용일 뿐이다** — 실제 답변을 저장할 때는 이 캐시된 인증 상태를 믿지 않고 서버가 매번 좌표를 다시 검증한다.

## 7. 사용한 기술

| 기술 | 용도 |
|---|---|
| `Timer.periodic` | 3분 주기 인증 재확인 |
| Flutter `StatefulWidget` + `dispose` | 탭을 떠날 때 타이머 정리 |

## 8. 문제와 해결

- **문제:** "전체 LIVE Q&A"에 뜬 질문에 답변 버튼을 달아야 하나?
- **원인:** 전체 목록은 관광지 구분 없이 섞여 있어서, 사용자가 그중 어느 곳에도 있지 않을 수 있다.
- **해결:** 이 목록은 **조회 전용**으로 못 박았다. 답변은 "내 현장 Q&A"(GPS 인증된 곳)나 관광지 상세페이지에서만 가능하다. 서버 쪽 `/questions/recent`도 조회 전용 엔드포인트로 분리했다.
- **배운 점:** 목록 화면을 만들 때 "여기서 무엇을 할 수 있나"를 먼저 정해야 한다. 조회 전용 목록과 조작 가능한 목록은 아예 다른 위젯으로 나누는 편이 안전하다.

## 9. 의사결정

> **정책 원문 없음** — 이 구조는 사용자가 채팅으로 준 정책이었으나, 원문이 보존되지 않았다. 아래는 실제 구현된 동작을 기준으로 재구성한 것이다. (원래 기록돼 있던 `decisions.md`가 하네스 개편 과정에서 폐기됐고, 원문은 옮겨지기 전에 사라졌다.)

| 쟁점 | 결정 | 근거 |
|---|---|---|
| Live 페이지의 중심 | **Q&A** (제보 아님) | 제보는 상세페이지에서 계속 볼 수 있다. Live 탭의 고유 가치는 "지금 답변이 필요한 질문"이다 |
| GPS OFF일 때 구조 | HOT SPOTS → 전체 LIVE Q&A | 인증 없이도 볼 것이 있어야 한다 |
| GPS ON + 인증 성공 | 내 현장 Q&A → HOT SPOTS → 전체 LIVE Q&A | 내가 답할 수 있는 것이 맨 위에 와야 행동으로 이어진다 |
| 개별 제보 스트림 | **Live 메인에서 제거** | Q&A가 그 자리를 차지한다. 데이터는 DB에 그대로 있고 상세페이지에서 확인 가능 |
| 인증 상태 유지 | 영구가 아니라 **3분마다 재확인** | 자리를 뜬 사람에게 "답변하기"가 계속 보이면 안 된다 |
| GPS 토글 기본값 | **꺼짐** | 탭을 열자마자 권한 팝업이 뜨는 건 나쁜 경험이다 |
| "전체 LIVE Q&A"에서 답변 | **불가.** 조회 전용 | 그 관광지 현장에 있다는 보장이 없다 |

## 10. 배운 것

- 같은 화면이라도 **사용자 상태(GPS 인증 여부)에 따라 구성이 통째로 달라질 수 있다.** 이걸 조건부로 위젯 하나를 숨기는 식이 아니라 "구조 A / 구조 B"로 명시하면 코드도 읽기 쉬워진다.
- 임시 구현("Q&A가 없으니 제보로 대신")을 넣을 때는 **원래 무엇이 들어갈 자리인지 주석으로 남겨야** 나중에 제자리를 찾아준다. 실제로 이전 구현에 그 메모가 있어서 교체 지점이 분명했다.

## 11. 현재 한계

- 인증 후보를 **가장 가까운 1곳만** 확인한다. 그곳이 실패하면 두 번째 후보는 시도하지 않는다.
- 3분 주기 재확인은 Live 탭이 화면에 떠 있을 때만 돈다.
- "내 현장 Q&A"에 답변할 질문이 없으면 빈 상태가 된다 — 질문이 없는 시간대에는 이 영역의 가치가 없다.
- 답변이 달렸을 때 질문자에게 알릴 방법이 없다(기능 8 미구현).
