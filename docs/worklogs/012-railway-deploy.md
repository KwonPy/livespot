# Railway 배포

## 1. 한 줄 요약
그동안 내 컴퓨터에서만 실행되던 서버(백엔드)와 화면(프론트)을, 누구나 인터넷 주소로 들어와서 쓸 수 있도록 "Railway"라는 곳에 올렸다.

## 2. 왜 만들었는가
지금까지는 내 컴퓨터를 켜고 서버 프로그램을 직접 실행해야만 앱이 동작했다. 내 컴퓨터를 끄면 앱도 같이 멈춘다. 다른 사람이 아무 때나 앱을 쓰려면, 24시간 꺼지지 않는 곳에 서버를 올려둬야 하는데, 그 "24시간 켜져 있는 컴퓨터"를 빌려주는 서비스가 Railway다.

## 3. 구현한 것
- **백엔드(서버) 쪽**: Railway에 올릴 때 몇 가지를 서버 코드에 맞춰줘야 했다.
  - Railway는 서버가 몇 번 문(포트)으로 손님을 받을지 매번 랜덤하게 정해준다. 원래 코드는 "8080번 문으로만 받는다"고 고정돼 있어서, "Railway가 알려주는 문 번호로 받아라"로 바꿨다.
  - 서버가 켜질 때마다 데이터베이스(정보를 저장하는 큰 장부)를 최신 모양으로 자동 정리하도록 했다.
  - Railway가 주는 데이터베이스 주소가 우리 코드가 이해하는 형식과 조금 달라서, 서버가 켜질 때 자동으로 형식을 맞춰 바꿔주는 부분을 추가했다.
- **프론트(화면) 쪽**: 화면 코드 안에 "서버 주소 = 내 컴퓨터"라고 고정되어 있던 걸, "화면을 만들 때 어떤 서버 주소를 쓸지 그때그때 정할 수 있게" 바꿨다. 그리고 화면을 인터넷에 띄우는 방법도 새로 만들었다.
- Railway 안에 `livespot`이라는 새 작업 공간을 만들고, 그 안에 데이터베이스, 서버, 화면 이렇게 3개를 각각 따로 올렸다.

## 4. 동작 흐름
```
사람이 화면 주소로 접속
→ Railway가 미리 만들어둔 화면 파일을 보여줌
→ 화면이 서버 주소로 "정보 좀 줘" 하고 요청
→ Railway에 올라간 서버가 요청을 받음
→ 서버가 데이터베이스에서 정보를 찾아옴 (또는 저장함)
→ 서버가 화면에 정보를 돌려줌
→ 화면에 나타남
```

## 5. 주요 파일
- `livespot_backend/Dockerfile`: 서버를 어떻게 켤지 적어둔 설명서. Railway가 알려주는 문 번호를 쓰게 하고, 켜질 때 데이터베이스를 자동으로 정리하는 부분을 추가했다.
- `livespot_backend/app/config.py`: Railway가 주는 데이터베이스 주소를 서버가 이해할 수 있는 모양으로 자동으로 바꿔주는 부분을 추가했다.
- `livespot_app/lib/config/constants.dart`: 화면이 어떤 서버 주소로 요청을 보낼지 정하는 부분. 이제 화면을 만들 때 원하는 주소를 끼워 넣을 수 있다.
- `livespot_app/Dockerfile`, `livespot_app/nginx.conf`: 화면을 인터넷에 띄우기 위해 새로 만든 설명서들.

## 6. 핵심 코드 / 개념
- 화면 코드에 "서버 주소를 못 정해주면 내 컴퓨터 주소를 쓰고, 정해주면 그 주소를 써라"라는 규칙을 넣었다. 그래서 평소 내 컴퓨터에서 테스트할 때는 그대로 잘 되고, Railway에 올릴 때만 진짜 서버 주소를 끼워 넣으면 된다.
- 서버가 켜질 때 "① 데이터베이스 정리 → ② 서버 켜기" 순서로 딱 정해뒀다. 데이터베이스가 정리되기 전에 서버부터 켜지면 오류가 날 수 있어서 순서를 강제했다.

## 7. 사용한 기술
- Railway의 명령어 도구(터미널에 글자로 명령을 치면 Railway가 알아서 서버를 올려주는 프로그램)를 이용해 배포했다.
- 화면(Flutter 웹)을 인터넷에 보여줄 때 "웹페이지를 손님에게 보여주는 담당자" 역할을 하는 nginx라는 프로그램을 같이 썼다.

## 8. 문제와 해결

**문제 1 — 설정을 바꿔도 "바뀐 게 없다"고 무시당함**
- 원인: Railway 명령어 중 한 종류가 이 환경에서는 계속 값을 제대로 못 받아들였다 (도구 자체의 문제로 보임).
- 해결: 같은 내용을 다른 방식(글 뭉치 하나로 통째로 보내는 방식)으로 바꿔서 보내니 정상적으로 반영됐다.

**문제 2 — 서버를 처음 올렸는데 "그런 폴더 없다"며 실패**
- 원인: "서버 파일들은 이 폴더 안에 있다"고 Railway에 알려줄 때 `livespot_backend`라는 폴더 이름을 적었는데, 정작 파일을 올리는 명령은 이미 그 폴더 안에서 실행했다. 그러다 보니 Railway 입장에서는 폴더 안에 또 같은 이름의 폴더를 찾다가 없어서 실패했다.
- 해결: "이 폴더 안에 있다"는 표시를 지워서(비워서) 해결했다.
- 배운 점: 폴더 위치를 알려주는 설정은, 파일을 올리는 명령을 "어디서" 실행했는지와 반드시 맞춰야 한다.

**문제 3 — Railway가 알아서 서버 종류를 잘못 판단해서 빌드 실패**
- 원인: Railway는 원래 "이건 파이썬 서버구나" 하고 자기가 알아서 켜는 방법을 판단하려 하는데, 그 자동 판단 과정에서 오류가 났다. 우리는 이미 "이렇게 켜라"는 설명서(Dockerfile)를 직접 만들어뒀는데 그걸 안 쓰고 있었다.
- 해결: "자동 판단 하지 말고 우리가 만든 설명서(Dockerfile)대로 켜라"고 명확히 지정했다.

**문제 4 — 배포 후 지도 화면에 "내 주변 관광지"가 하나도 안 뜸**
- 원인: 배포하면서 "서울 지역만 보여준다"는 설정을 임의로 켜뒀는데, 서울이 아닌 곳(예: 경희대 국제캠퍼스)에서 접속하면 주변에 보여줄 서울 관광지가 없어서 결과가 0개로 나왔다.
- 해결: 사용자에게 확인받고 "지역 상관없이 다 보여준다"로 설정을 바꾸고 다시 배포했다.
- 배운 점: 사용자가 실제로 느끼는 동작에 영향을 주는 설정값은 마음대로 정하지 말고, 배포 직후 실제 상황처럼 꼭 테스트해봐야 한다.

## 9. 의사결정

### 사용자가 준 정책 (원문)
이번 작업은 채팅으로 받은 정책 원문은 없었다. 진행 중 상황마다 사용자에게 그때그때 확인받으며 진행했다.

### 정책에 없어서 확정한 것
| 쟁점 | 결정 | 근거 |
|---|---|---|
| Railway 무료 요금제로는 더 못 만든다고 막힘 | 사용자가 유료로 바꿈, 안 쓰는 예전 테스트 프로젝트는 지움 | 사용자가 직접 확인하고 결정함 |
| 비밀 열쇠(API 키) 옮기는 방법 | `.env`라는 비밀 파일은 Claude가 직접 들여다보지 않고, 사용자가 터미널에서 직접 옮기게 함 | 비밀 값이 대화창에 그대로 보이지 않게 하려고 |
| 지역 제한 설정 처음 값 | 처음엔 "서울만" 보이게 했다가, 문제가 생겨서 "전국 다 보이게"로 다시 바꿈 | 아직 서울로만 서비스를 하기로 확정하지 않았다고 판단 |
| 데이터 저장 방식 | 파일 하나짜리 간단한 저장 방식(SQLite) 대신, Railway의 정식 데이터베이스(Postgres)를 새로 붙임 | 로그인, 제보, 포인트처럼 사람들이 쌓아가는 정보는 서버를 새로 올릴 때마다 사라지면 안 되기 때문 |

## 10. 배운 것
- "이 폴더 안에 서버 파일이 있다"는 설정과, 실제로 파일을 올리는 위치는 항상 짝이 맞아야 한다. 안 맞으면 조용히 실패한다.
- 서버 설정값(환경변수)을 바꿔도, 서버를 껐다 다시 켜기 전까지는 그 값이 반영되지 않는다. 값만 바꾸고 재시작을 안 하면 아무 일도 안 일어난 것처럼 보인다.
- 화면을 인터넷에 보여주는 nginx라는 프로그램은, 설정 파일 안에 있는 `${이런 표시}`를 실제 값으로 자동으로 바꿔주는 기능이 있다. 그런데 아무 설정 없이 쓰면 상관없는 다른 글자들까지 건드려서 오히려 설정이 깨질 수 있어서, "이 이름만 바꿔라"고 범위를 정확히 정해줘야 한다.

## 11. 현재 한계
- 카카오 API 키는 아직 발급받지 못해서 설정하지 못했다. (없어도 서버는 정상적으로 돌아가고, 카카오 관련 기능만 못 쓴다.)
- 배포를 위해 로컬에서 고친 파일들(Dockerfile 2개, config.py, constants.dart, nginx.conf)은 아직 git에 저장(커밋)하지 않았다.
- Railway 화면(웹사이트)에서 직접 값을 입력했는데 실제로는 반영이 안 되는 일이 있었다. 왜 그랬는지 정확한 원인은 못 찾았고, 결국 터미널 명령으로 다시 입력해서 해결만 했다.

## 12. 다음 단계
- 로컬에서 고친 파일들을 git에 저장(커밋)하기.
- 카카오 API 키를 받으면 서버 설정에 추가하고 다시 배포하기.
- 서비스 지역을 "서울만"으로 다시 정할지, "전국"으로 계속 둘지 나중에 다시 상의하기.
- 지금은 Railway가 공짜로 주는 임시 주소(`...up.railway.app`)를 쓰고 있는데, 나중에 우리만의 도메인 주소를 연결하는 것도 남은 일.
