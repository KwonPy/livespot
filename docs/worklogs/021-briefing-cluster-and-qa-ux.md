# AI 브리핑 제보 종합 + Q&A 알림/UX 정리

## 1. 한 줄 요약
AI 브리핑이 현장 제보를 "가장 최근 1건"만 보던 걸 "1시간 이내 연속 제보는 종합"하도록 바꾸고, 알림에서 질문을 확인할 때 답변까지 바로 이어지도록 이동 경로를 단순화했고, Q&A 카드를 누를 때 나던 물결 효과를 없앴다.

## 2. 왜 만들었는가
- **AI 브리핑**: 기존엔 오늘 제보가 여러 건이어도 가장 최근 1건의 혼잡도/대기시간/주차 상태만 프롬프트에 넣었다. 그런데 짧은 시간 안에 여러 사람이 연달아 제보했다면(예: 10분 간격으로 3명), 그건 "한 사람의 순간적인 관찰"이 아니라 "지금 이 상황이 맞다"는 여러 명의 동시 확인이다. 이 정보를 버리고 있었다.
- **알림 → 답변 흐름**: "질문이 도착했어요" 알림을 눌렀는데 정작 답변을 할 수 없다는 걸 사용자가 발견했다. 조사해보니 일부러 그렇게 만들어 둔 것이었다 — GPS 인증 없이 답변할 수 있는 우회로가 생기지 않도록. 하지만 사용자 입장에서는 "질문이 왔다"는 알림을 누르면 답까지 하고 싶은 게 자연스러운 동선이라, 안전장치는 유지하되(답변은 여전히 상세페이지에서 GPS 재인증을 거쳐야 함) 중간에 읽기만 하는 화면을 거치지 않고 바로 상세페이지로 보내기로 했다.
- **물결 효과 제거**: Q&A 카드를 눌러 답변을 펼칠 때마다 카드 전체에 물결(ripple) 효과가 나는 게 사용자에게는 "깜빡거리는 것"처럼 느껴져 거슬린다는 피드백.

## 3. 구현한 것

### 3-1. AI 브리핑 — 제보 시간창 클러스터링
- 최근 제보부터 시간을 거슬러 올라가며, **바로 이전 제보와의 간격이 1시간을 넘지 않는 동안은 계속 묶는다.** 1시간 넘는 지점이 나오면 거기서 끊는다.
- 묶인 제보가 2건 이상이면 혼잡도/대기시간/주차 상태를 각각 **최빈값**(가장 많이 나온 값, 동률이면 더 최신 값)으로 종합해서 브리핑 문장에 "최근 1시간 이내 연속 제보 N건을 종합한 현재 상황"이라고 밝힌다.
- 1건뿐이면 예전처럼 "가장 최근 제보"라고만 쓴다.
- 오늘 총 제보 건수(`report_count`)는 이 묶음과 별개로 그대로 유지 — "종합에 쓴 건수"와 "오늘 전체 건수"는 다른 숫자다.

### 3-2. 알림 "확인하기" → 관광지 상세페이지 직행
- 예전엔 알림을 누르면 서버에서 해당 질문을 다시 조회해 읽기 전용 바텀시트(질문+답변만 보여주고 답변 버튼은 없음)를 띄웠다.
- 이제는 질문을 따로 조회하지 않고 곧장 관광지 상세페이지로 이동한다. 상세페이지 안의 Q&A 영역(`QaSection`)에서 GPS 인증을 다시 거치면 그 자리에서 답변까지 쓸 수 있다.

### 3-3. Q&A 카드 탭 — 물결 효과 제거
- 질문 카드를 눌러 답변을 펼치고/접을 때 나던 Material 기본 물결(ripple) 효과를 껐다. 펼치고 접는 동작 자체는 그대로다.

## 4. 동작 흐름

**AI 브리핑**
```
사용자 여러 명이 짧은 간격으로 현장 제보 등록
→ DB reports 테이블에 시간순으로 쌓임
→ GET /spots/{id}/briefing 호출 시
   report_window.latest_cluster()가 "1시간 이내로 이어진 묶음"만 골라냄
→ 묶음이 여러 건이면 혼잡도/대기/주차를 최빈값으로 종합
→ Gemini 프롬프트에 "종합한 현재 상황"으로 명시해서 전달
→ Gemini가 문장 생성 → 앱 화면에 표시
```

**알림 → 답변**
```
현장에 있던 사용자가 질문 등록
→ 서버가 그 관광지 반경 안 사용자들에게 NEW_QUESTION 알림 생성
→ 앱이 WebSocket으로 신호를 받아 모달 표시
→ "확인하기" 클릭
→ (읽음 처리) → 관광지 상세페이지로 이동
→ 거기서 GPS 재인증 → 답변 작성
```

## 5. 주요 파일
- `livespot_backend/app/services/report_window.py`: `latest_cluster()` — 시간 간격으로 제보를 묶어서 돌려주는 함수
- `livespot_backend/app/services/gemini.py`: `BriefingMaterials`(제보 묶음을 받는 구조로 변경), `build_prompt()`(1건/여러 건 문구 분기), `build_signature()`(캐시 키에 묶음 크기 반영)
- `livespot_backend/app/api/spots.py`: 브리핑 엔드포인트에서 `latest_cluster()` 호출로 교체
- `livespot_backend/app/config.py`: `BRIEFING_REPORT_CLUSTER_GAP_HOURS`(묶음을 끊는 간격, 기본 1시간), `BRIEFING_REPORT_CLUSTER_MAX`(묶음 조회 상한, 기본 10건)
- `livespot_app/lib/utils/notification_open.dart`: 알림 탭 시 이동 로직 — 질문 조회 없이 상세페이지로 바로 이동하도록 단순화
- `livespot_app/lib/widgets/qa_section.dart`: Q&A 카드 `InkWell`에서 물결 효과 제거

## 6. 핵심 코드 / 개념

**최빈값 종합 (동률이면 최신값 우선)**
```python
def _mode_latest(values: List[Optional[str]]) -> Optional[str]:
    present = [v for v in values if v]
    counts = Counter(present)
    best = max(counts.values())
    for v in present:          # values는 항상 최신순으로 들어온다
        if counts[v] == best:  # 가장 많이 나온 값 중, 먼저(=더 최신) 나오는 것을 택함
            return v
```
"혼잡/혼잡/보통" 3건이면 "혼잡"이 최빈값. "혼잡/보통" 2건처럼 동률이면 더 최근에 올라온 쪽을 택한다.

**시간창 클러스터링 (제보를 어디서 끊을지)**
```python
gap = timedelta(hours=gap_hours)
cluster = [ordered[0]]                      # 최신 제보부터 시작
for prev, curr in zip(ordered, ordered[1:]): # 최신→과거 순으로 두 개씩 비교
    if prev.created_at - curr.created_at > gap:
        break                                # 간격이 1시간 넘으면 여기서 멈춤
    cluster.append(curr)
```

## 7. 사용한 기술
새로 도입한 라이브러리는 없다. Python 표준 라이브러리 `collections.Counter`(최빈값 계산)를 처음 이 파일에서 사용했다.

## 8. 문제와 해결
- 문제: 없음 (버그 수정이 아니라 정책 변경 + UX 개선)
- 원인: 해당 없음
- 해결: 해당 없음
- 배운 점: 알림 모달에서 읽기 전용 시트로 보내던 기존 설계는 "버그처럼 보이지만 사실은 의도된 안전장치"였다. 이런 사례는 일반화해 남길 만한 교훈이라, `.claude/skills/livespot-contract/references/bug-patterns.md`에 "의도된 제약을 버그로 오인하기 전에 주석·설계 의도부터 확인" 패턴으로 추가하는 것을 다음 기회에 고려한다(이번 세션에서는 추가하지 않음 — 사례가 1건뿐이라 아직 패턴이라 부르기엔 이름).

## 9. 의사결정

### 사용자가 준 정책 (원문)

> 음 맞긴한데, 최신정보만 주지말고, 현장제보가 여러개인 경우에는 시간간격으로 판단하자. 제보간 시간간격이 1시간이 넘어가면 최신제보만 반영하고, 1시간 이내인 경우에는 여러개 제보를 종합해서 브리핑 제공하는걸로

> 확인하기를 누르면 바로 관광 상세페이지로 가도록 해줘. 바텀시트는 삭제하고.

> live page에서 gps 인증을 하면 현장 Q&A 목록에 질문이 뜨는데, 그거 누를때 마다 깜빡깜빡 거리는 효과 삭제해줘.

### 정책에 없어서 확정한 것

| 쟁점 | 결정 | 근거 |
|---|---|---|
| 종합할 때 혼잡도/대기/주차를 어떻게 합칠까(평균? 최신?) | 최빈값, 동률이면 최신값 우선 | 이 값들은 카테고리(EASY/NORMAL/BUSY 등)라 평균을 낼 수 없다. "여러 명이 공통으로 말하는 상황"이 최빈값에 가장 잘 담긴다고 판단 |
| 클러스터 조회 자체의 상한 | 최대 10건(`BRIEFING_REPORT_CLUSTER_MAX`) | 1시간 안에 비정상적으로 많은 제보가 몰려도 프롬프트가 무한히 커지지 않게 하는 방어용 상한. 실제로는 `gap_hours` 판정이 먼저 걸릴 것으로 예상 |
| "깜빡임" 요청이 카드 물결인지 전체 화면 애니메이션인지 | 먼저 물어봐서 카드 물결로 확정, 처리 후 사용자가 "카드는 됐는데 전체가 번쩍인다"고 재보고 | 최초 요청이 두 가지로 해석될 수 있어 질문으로 확인했다. 재보고로 새 조사가 필요해짐(11절 참고) |
| 알림에서 답변까지 가는 길에 안전장치(읽기 전용 시트)를 없애도 되는가 | 없앰. 단, 답변 가능 여부를 결정하는 GPS 인증 자체는 그대로 상세페이지에 남겨둠 | 사용자의 명시적 지시. 안전장치의 목적(GPS 미인증 답변 차단)은 상세페이지 GPS 재인증으로 여전히 지켜지므로, 중간 시트를 없애도 우회로가 생기지 않는다 |
