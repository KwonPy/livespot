# auto-push — 커밋 후 GitHub push

**전제**: 사용자가 명시적으로 "GitHub 업데이트", "푸시", "커밋하고 푸시" 등을 요청했을 때만 이 스킬을 사용한다. 다른 작업(코드 수정, 문서 반영 등) 도중에 자동으로 커밋·푸시하지 않는다.

## 절차

1. **Git 상태 확인**
   ```bash
   git status
   ```
   변경된 파일과 브랜치를 확인한다.

2. **커밋 메시지 확보**
   - 사용자가 이번 요청에서 커밋 메시지를 직접 지정했다면 그 메시지를 그대로 쓴다.
   - 지정하지 않았다면 **임의로 지어내지 말고 사용자에게 커밋 메시지를 물어본다.** 메시지를 받기 전까지 커밋을 진행하지 않는다.

3. **변경 파일 추가**
   ```bash
   git add <해당 파일들>
   ```
   `git add -A`나 `git add .` 대신 실제로 바뀐 파일을 지정한다. 커밋 전 `git status`로 스테이징된 내용에 `.env`, 자격증명 등 민감 파일이 섞였는지 반드시 확인한다.

4. **커밋**
   사용자가 지정한 메시지로 커밋한다. 메시지 끝에 다음 줄을 추가한다:
   ```
   Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>
   ```

5. **push**
   현재 브랜치가 추적하는 원격 저장소·브랜치로 push한다.
   ```bash
   git push
   ```
   원격/브랜치가 설정되어 있지 않으면 사용자에게 확인 후 `-u`로 설정한다. **force push는 하지 않는다.**

6. **CI·테스트·lint는 실행하지 않는다.** 이 스킬의 범위가 아니다.

7. **배포는 Railway 자동 배포에 맡긴다.** push 이후 별도의 배포 명령을 실행하지 않는다.

8. **결과 보고**
   커밋 해시(앞 7자)와 push된 브랜치, 원격 저장소만 짧게 보고한다. 그 외 부연설명은 생략한다.

## 하지 않는 것

- 커밋 메시지를 임의로 작성하는 것
- `--no-verify`, `--force` 등 안전장치를 우회하는 것
- CI/테스트/lint 실행
- Railway 배포를 직접 트리거하는 것 (push만 하면 자동 배포됨)
